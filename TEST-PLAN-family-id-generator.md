## Affected Pages/Routes
- `/admin/family-ids` — admin page: Generate button, summary, unattached/ambiguous bucket, manual assign, re-run keeps IDs. Why: core generator UX.
- `/gate` — gate screen (admin + supervisor role switch): keypad input, camera QR scan, hardware-scanner input, NOT-FOUND state. Why: safety-critical flow.
- `/admin/bulk` (BulkUpload) — CSV import with new Gov-id/Bus/Mode columns, header-name mapping, Name+Class matching with ambiguity flags. Why: data ingestion.
- Parent portal `ChildrenView` (M3) — family ID shown for each child. Why: parent visibility.

## Key Interactions to Verify
- Admin clicks **Generate** → family IDs appear for all families; summary shows counts (assigned/kept/unattached).
- Admin clicks **Generate again** → existing IDs unchanged (idempotent), only missing ones assigned.
- Import a CSV with columns in a different order → rows still map correctly (header-name mapping).
- Import rows with duplicate Name+Class → flagged ambiguous, land in the bucket, not silently assigned.
- Gate: type a valid family ID → matching students shown with name, grade, transport, parent phone.
- Gate: type/scan an unknown ID → clear NOT-FOUND state, and the lookup is audit-logged.
- Gate: hardware barcode scanner input → treated as typed input, same result.
- Gate: camera scan of card QR → same result as typed.
- Gate: teacher or parent account → cannot open /gate (role-gated).
- Generate runs → audit-logged (who, when, counts).
- Parent logs in → sees their family ID on ChildrenView (M3).

## Edge Cases
- Student with no parentId and no phone → lands in unattached bucket; manual assign works.
- Two students with identical Name+Class → ambiguity flag, not auto-assign.
- Transport values: `nb`, empty, bus number, `WALKER`, `CAR` → normalized consistently everywhere (import, edit, print).
- RPC error during Generate → clear toast, no partial state, Generate re-runnable.
- Double-click Generate → only one generation (RPC is transactional/idempotent).
- Gate lookup with zero students → empty-state prompt ("scan or type a family ID").
- QR encode failure → card still prints without QR + toast (never a silent blank).
- Camera permission denied / no camera → keypad fallback still available.
- Unknown/typo'd family ID → NOT-FOUND state + audit log entry.
- Mobile viewport: gate screen usable one-handed in daylight (contrast, big numerals).

## Critical Paths
1. Import sheet CSV (Gov-id/Bus/Mode) → match to students → Generate family IDs → print cards + QR → gate lookup finds kids by type/scan → release decision made.
2. Re-run Generate a month later after new students → existing IDs preserved, new families assigned.
3. Wrong-family-ID or unknown card at gate → NOT-FOUND, no release, no silent match.
