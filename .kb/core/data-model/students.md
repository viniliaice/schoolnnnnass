# students

## Columns

| Column | Type | Description |
|--------|------|-------------|
| `id` | `text` PK | Primary key — the **System ID** (`student-<epoch_ms>-<hash6>`, generated by `create_student`). Every import, report and RPC uses this; there is no second student identifier. |
| `name` | `text` | Student full name |
| `className` | `text` | FK-like reference to class name string (CURRENT class; history lives in `student_enrollments`) |
| `parentId` | `text` | FK → profiles.id (the parent/guardian) |
| `govId` | `text` | Government/admission ID from the transport sheet (unique when normalized) |
| `parentPhone` | `text` | Parent phone from the sheet's SECOND NUMBER column |
| `transport` | `text` | Bus number, `WALKER`, `CAR`, `DRIVER` or `LEFT` (left the school) |
| `familyId` | `text` | Zero-padded 4-digit family ID (`0421`); `MBK-` prefix is display-only |
| `status` | `text` | **`active` \| `former`** (NOT NULL DEFAULT `active`, `students_status_check`). `former` = left the school; the row and all of its history are preserved. Added by `20261008_former_students_cleanup.sql`. |
| `statusUpdatedAt` | `timestamptz` | When `status` last changed (denormalized for the Former Students directory) |
| `statusUpdatedBy` | `text` | profiles.id of whoever changed `status` last |
| `createdAt` | `timestamptz` | Row creation timestamp |

Rows written before 20261008 have no `status` value on the client, so every reader
treats `undefined`/`null` as `active` (`isActiveStudentRecord` in
`lib/db/students.ts`) — nobody disappears from a roster because of a missing
column.

## Indexes

| Name | Column(s) |
|------|-----------|
| `idx_students_parentId` | `parentId` |
| `idx_students_className` | `className` |
| `idx_students_name_match_key` | `name_match_key(name)`, `className` |
| `uniq_students_gov_id` | `gov_id_match_key(govId)` (unique, partial) |
| `idx_students_status` | `status` |
| `idx_students_status_class` | `status`, `className` |
| `idx_students_status_updated` | `statusUpdatedAt DESC` WHERE `status = 'former'` |

## Status semantics

`status = 'former'` is set **together with** `transport = 'LEFT'`, because the
family-ID/gate features already exclude `LEFT` students (family-ID generation,
family cards, print batches, `gateEligibility`, `record_release`,
`attach_students_to_authorized_pickup`). Marking a student former therefore
removes them from active rosters AND stops them getting a gate card, without
re-typing any of that safety-critical SQL. The previous `transport` value is
stored in `student_status_changes."previousTransport"` so a restore is exact.

Nothing else changes: `name`, `id`, `className`, `parentId`, `parentPhone`,
`govId`, `familyId` and every child row (exams, attendance, homework,
quiz_attempts, report_comments, student_enrollments, student_promotions,
release_log, authorized_pickup_students, messages) are preserved.

Writes only happen through admin-gated SECURITY DEFINER RPCs — there is no
client INSERT/UPDATE/DELETE policy on this table (`20260906d_rls_lockdown.sql`).
